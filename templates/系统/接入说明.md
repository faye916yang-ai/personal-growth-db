# 接入说明

让主人在**任何项目、任何对话**里用 AI 做完事，AI 都知道要往资料库里记。接入就是把下面这段“全局规则”写进 AI 工具的全局规则位置。

## 接入的规矩（AI 必须遵守）

1. **先说明再写**：告诉主人要写在哪、写什么，主人同意了再写
2. **只新增**：文件已存在就在末尾追加，不改、不删原有内容；已经有这段就不重复写
3. **写完自测**：规则文件里有这段 → 资料库能 `git pull`、`git push` → 新开一个对话问“你知道我的个人成长资料库吗？做完事要记到哪？”，答得上来才算成功
4. 接入后在 `设置.md` 的“AI 工具”表里登记

## 各工具的全局规则写在哪

| 工具 | 位置 | 怎么写 | 位置确认了吗 |
|---|---|---|---|
| Claude Code | `~/.claude/CLAUDE.md` | 追加下面的全局规则 | 已确认 |
| Codex | `~/.codex/AGENTS.md` | 追加下面的全局规则 | 待实测 |
| Cursor | `~/.cursor/rules/personal-growth-db.mdc` | 新建，开头加上下面“Cursor 文件头”，再接全局规则 | 有人用过，待实测 |
| WorkBuddy | 待确认 | 先问工具自己：“你的全局规则或长期记忆写在哪？”；不确定就让主人粘贴到设置里的自定义指令或记忆 | 待实测 |
| DeepSeek Harness | 待确认 | 同上 | 待实测 |
| 其他能写文件的工具 | 工具自己的全局规则文件 | 同上 | |

Cursor 文件头：

```
---
description: 个人成长数据库
alwaysApply: true
---
```

> 工具更新后位置可能会变。发现上表不对，告诉主人，并把正确的位置记进 `设置.md`。

## 全局规则（写进去的内容）

把 `<资料库路径>`、`<电脑名>` 换成 `设置.md` 里的真实值：

```markdown
# 我的个人成长数据库

我有一个个人成长数据库：`<资料库路径>`（GitHub 私有仓库）。它记录我每天做的事、踩的坑、学到的东西，并沉淀成我的做事方法和能力。完整规则在该目录的 `AGENTS.md`。

**不管你现在在哪个文件夹工作，都要按下面的方式和资料库配合。**

1. **判断要不要记**：记录范围以资料库的 `我是谁/记录范围.md` 为准。无关的临时操作不记；拿不准就在结束时问我“这件事要记进资料库吗？”
2. **开始前**：读资料库的 `能力/README.md` 和 `成长/踩坑避坑库.md` 里相关的部分。有对应的 SOP 就照着做；有相关的坑，先提醒我
3. **做的过程中**：按“一件事”留意值得记的时刻（卡了好几轮才解决、换了方向、学到新东西、我做了某个判断），不要逐条指令记，也不要打断我
4. **一件事做完，或对话结束时**：读资料库的 `AGENTS.md`，按“怎么记”的格式，把事件记录写进 `每日/YYYY-MM/YYYY-MM-DD-<电脑名>.md`。照着 SOP 做的，在 SOP 的执行记录里加一行
5. **写完后**：在资料库目录里 `git pull --rebase`，再 commit 和 push。推送失败时告诉我，不要丢掉记录
6. 最后用一两句话告诉我记了什么

注意：密码、密钥、客户个人信息绝不写进资料库；资料库只追加，不删除我写的内容；当前项目自己的规则照常遵守。我问到资料库的问题时，先读资料库的 `系统/常见问题.md`。
```

## 接入新电脑

主人在新电脑的 AI 工具里说“把我的成长资料库接到这台电脑上”，并给出仓库地址：

1. 问这台电脑叫什么（英文字母和数字），登记进 `设置.md`
2. `git clone <仓库地址> <资料库路径>`。第一次可能要登录 GitHub，让主人在弹出的窗口里登录
3. 按上面的规矩，把全局规则写进这台电脑上的工具
4. 推送一次，确认能同步

## 只能聊天的 AI（网页版 ChatGPT、DeepSeek、豆包、Grok 等）

它们写不了资料库，只负责“存档”。让主人把下面这段粘贴到它们的“自定义指令”或“记忆”里（要写明对所有对话生效）：

```
请把下面这段作为长期规则，在之后所有对话里都生效。

我有一个个人成长数据库，记录我做的事、踩的坑、学到的东西。在这里和我对话时：
1. 判断这件事值不值得记：工作、项目、学习、我在做的长期的事都值得记；随手的闲聊不记，拿不准就在结尾问我“要存档吗？”
2. 按“一件事”留意值得记的时刻（卡了好几轮才解决、换了方向、学到新东西、我做了某个判断），不要打断我
3. 我说“存档”时，按这个格式输出：
   - 目标 / 过程 / 卡点和突破 / 结果（没做完写“进行中”和下一步）/ 收获 / 值得留下的（可写进周报述职的、可做成内容的）
   - 好用的提示词：原样列出来
   - 可沉淀的：新的坑、可以整理成 SOP 的做法
4. 中文，简洁。密码、密钥、客户个人信息绝不写进总结。
```

主人拿到总结后，复制给能写文件的 AI，前面加“记一下：”。
