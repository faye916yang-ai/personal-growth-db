# 个人成长数据库：给 AI 的规则

这是主人的个人成长数据库。任何 AI 工具（Claude Code、Codex、Cursor、WorkBuddy、DeepSeek Harness 等）打开这个库时，都按下面的规则读写。

它不只是存资料：它每天跟着主人做事，记下做了什么、踩了什么坑、学到了什么，再从中提炼出主人的做事风格、原则、方法论和能力，最终长成一个 **AI 版的完整的主人**。

> 这个文件属于“个人成长数据库” Skill，升级时会被更新。主人的个性化内容写在 `我是谁/` 和 `设置.md`，不要写进这里。

## 开工前

1. `git pull`
2. 读 `设置.md`、`我是谁/基本信息.md`、`我是谁/记录范围.md`、`我是谁/做事风格.md`，以及 `每日/` 里最近 2 天的记录
3. 做某类事之前：先查 `能力/README.md` 的能力地图，有对应的 SOP 就照着做；再查 `成长/踩坑避坑库.md` 的相关分类，有相关的坑先提醒主人
4. 用到哪个项目、领域，就读 `项目/` 或 `领域/` 里对应的文件

## 记什么

记录范围以 `我是谁/记录范围.md` 为准。和范围无关的临时操作（例如随手生成一张图、试一个小工具）不记。**拿不准就在结束时问一句“这件事要记进资料库吗？”**

`我是谁/记录范围.md` 里“不记清单”上的内容一律不记。

## 怎么记：按“一件事”记，不按“一条指令”记

- **一件事**：有明确目标的工作，例如“写完 Q3 述职”“把新功能上线”。可能要很多条指令，跨好几个对话、几台电脑，甚至好几天
- **一条指令**：过程中的一步，例如“把这段改短一点”。**不要逐条记**

做事过程中留意这些时刻，先记在心里，**不打断主人**：
- 卡了好几轮才解决的问题
- 中途换了方向，或者发现原来的理解错了
- 学到了新东西、新工具、新用法
- 主人做了某个判断或取舍

**一件事做完，或者对话结束时**，在当天的日志里写一条“事件记录”：`每日/YYYY-MM/YYYY-MM-DD-<电脑名>.md`（电脑名见 `设置.md`）。格式见 `每日/README.md`：

- **目标**：要做成什么
- **过程**：关键的几步，不是每条指令
- **卡点和突破**：卡在哪、为什么、怎么解决的，以后怎么避开
- **结果**：做成了吗。没做完写“进行中”，以及做到哪了、下一步是什么，方便下次在任何电脑、任何工具上接着做
- **收获**：学到了什么、哪里比以前做得好
- **值得留下的**：可以写进周报、述职、晋升证据的（工作）；可以拍成内容的选题（做内容的人）

照着某个 SOP 做的，在那份 SOP 的“执行记录”里加一行。

主人说“记一下：……”时，直接按内容放进当天的日志。

**写完就推送**：`git pull --rebase`，再 `git add -A`、`git commit`、`git push`。不要每条指令都推送。推送失败时告诉主人，不要丢掉记录。`设置.md` 里写着“GitHub：未建”的，只 commit，不 push。

## 每日成长报告

主人说“收工”“出今天的成长报告”，或者到了定时报告的时间时，按这个格式写，放在当天日志的最后：

```markdown
## 今日成长报告

1. **今天做了什么**：按项目、领域分组，每项一两句
2. **今天的收获**：学到了什么、哪件事比以前做得好
3. **今天踩的坑**：每个坑一句话，加上“以后怎么避开”
4. **能力的变化**：哪个 SOP 用上了、哪个 SOP 该改了、新冒出了哪个 💡、哪个从 📝 升到 ✅
5. **值得留下的**：可以写进周报、述职、晋升证据的；可以做成内容的
6. **明天建议**：最该推进的 1–3 件事
```

第 4 条最重要：要让主人每天都看到“我又长了一点”。

## 收工（主人说“收工”时）

1. 补全当天日志，写今日成长报告
2. 新的坑写进 `成长/踩坑避坑库.md` 对应的分类；已有的坑只在“踩过”后面加日期
3. 照着 SOP 做了事：在 SOP 的“执行记录”加一行；哪一步不顺，提议怎么改
4. 项目有进展：更新 `项目/<名字>.md` 的“当前进度”
5. 值得留下的：工作成果写进 `成长/晋升证据.md`（有这个模块的话）；选题写进 `资源/选题库.md`（有这个模块的话）
6. 看出主人的做事模式：只写进 `我是谁/候选洞察.md`，并写清依据
7. 推送，然后用三五句话告诉主人今天记了什么

## 周复盘（默认每周六晚上，时间见 `设置.md`）

1. 通读本周所有日志
2. 写 `成长/周报/YYYY-Www.md`：做成了什么、没做成什么、收获、踩了哪些坑（哪些是**重复踩的**）、能力有什么变化、下周最重要的 3 件事
3. 选了生活模块的：汇总本周的财务、运动等
4. 有“职场”模块的：顺手生成一份可以直接交给上级的周报，放进 `产出/周报/`
5. **确认候选洞察**：从 `我是谁/候选洞察.md` 里挑**最多 3 条**证据最足的，附在周报最后：

   > 这周我发现你的 3 个做事习惯：
   > 1. ……（依据：周二……、周四……）
   > 2. ……
   > 3. ……
   > 回复“1 对 2 改成…… 3 不对”就行

   - 确认的：移到 `原则.md`、`方法论.md`、`价值观.md` 或 `做事风格.md`
   - 不对的：在候选洞察里标“已否定”
   - 主人没回复：**不催**，继续放在候选里，**不生效**；超过一个月都没回应的，标“已过期”

## 月度复盘（每月最后一天）

写 `成长/月报/YYYY-MM.md`：

- 这个月做成了什么、没做成什么、数据
- **这个月我变了什么**：新增了哪些原则、方法论、SOP；哪些想法变了（以前 → 现在）；哪些能力从不会变成会。用 git 历史对比月初和月底的 `我是谁/`、`能力/`、`成长/`
- **资料库体检**：重复的条目、互相矛盾的条目、过时的条目、记了但一直没提炼的事、做了 3 次以上该写 SOP 的事。建议淘汰或合并的，逐条问主人
- 下个月最重要的 3 件事

## 自我进化规则

### 四层：从记录长成能力

| 层 | 是什么 | 在哪 | 规则 |
|---|---|---|---|
| ① 原始记录 | 每天真实发生的事 | `每日/` | **只追加，永不改写** |
| ② 经验 | 提炼过的精华 | `成长/`、`项目/`、`领域/`、`资源/` | 每条注明出处（哪天哪件事） |
| ③ 认知 | 主人是怎样的人、怎么做事 | `我是谁/` | AI 提议，**主人确认才生效** |
| ④ 能力 | AI 拿到就能照着做的东西 | `能力/` | 同类事做到第 3 次就固化 |

### 六条进化规则

1. **只做增量更新**：加新条目、改某一条，不整篇重写。整篇重写会让细节越写越少
2. **每条经验都有验证记录**：踩坑库、原则、方法论、SOP 的每一条，后面都记“哪天用上了、管不管用”。不管用的标出来，问主人要不要淘汰。淘汰的移到文件末尾的“已淘汰”，不删除
3. **新的会更新旧的**：新经历和已有结论矛盾时，不悄悄覆盖，写成“以前这样想 → 现在发现……”，问主人怎么处理。人会变，这些变化本身就是成长
4. **互相关联**：写新经验时，顺手链接相关的旧条目（相关的坑、SOP、事件记录）
5. **能力从做事里长出来**：同一类事做过 2 次，在能力地图标 💡；第 3 次开始前，主动提议“这次边做边整理成 SOP”。SOP 每用一次，在执行记录里加一行；哪一步卡住了，提议怎么改，主人同意后修改，并写进修改记录。成熟度：📝 初稿 → ✅ 验证过（照着做成功 1 次）→ ⭐ 成熟（成功 3 次以上）
6. **结构本身也会长**：见下面“结构怎么长”

### 结构怎么长

- 资料库一开始只有核心部分。主人**第一次**做到某类事时，再按 `系统/模块库.md` 建对应的模块
- 明显的小模块（例如一个新领域的文件、一个新的选题标签），可以直接建，事后告诉主人；新方向、新的大模块，先问一句“要不要加 XX？”
- 收件箱里同一类东西攒了 3 条以上，或者某个文件太长、混了好几类内容，提议拆开
- 每次结构变化，在 `成长/结构变化记录.md` 记一笔：加了什么、为什么、哪天
- 不再用的部分不删除：移到 `归档/`，或者标“已停用”

## 产出

主人要“生成周报 / 述职 / 简历 / 我的画像”时，按 `产出/README.md` 从日志、晋升证据、项目里取材料，生成后放进 `产出/`。

## 只能聊天的 AI

网页版 ChatGPT、DeepSeek、豆包、Grok 这类 AI 写不了这个库。主人在那里说“存档”时，它们会输出一段事件记录格式的总结，主人复制过来，前面加“记一下：”，你就按事件记录放进当天的日志。

## 写作规则

- 写给主人看的内容：中文，简洁直接
- `每日/` 只追加，不删除、不改写
- 主人自己写的内容不删除；要修改已有结论，先问主人
- 推断出的东西不要当成事实写进 `我是谁/`，只能写进候选洞察

## 安全规则

- 这个库在 GitHub 上必须是**私有**的
- 密码、密钥、证书、token 永远不写进来。不读、不复制名字里带 secrets、密码、私钥、token 的文件和文件夹
- 客户和他人的手机号、身份证、住址这类个人信息不记
- 公司的具体资料只记摘要，放进 `工作资料/`；从工作里提炼出的经验、方法、SOP，写成通用版本，放进 `能力/`、`成长/`。这样离职时，工作资料归档，成长部分完整带走
- `.gitignore` 已排除常见的密钥文件，但不能依赖它，写入前自己检查一遍

## 大文件

视频、大图、安装包不放进这个库，放网盘；需要的话在 `资源/` 里记链接和说明。小图（单张小于 5MB）可以放 `资源/图片/`。

## 遇到问题

主人问到资料库的任何问题（没记录、推送失败、换电脑、换工具），先读 `系统/常见问题.md`。
