# 第 3 步：生成资料库

## 1. 放在哪

问用户放在哪，默认 `~/个人成长数据库`。如果那里已经有同名文件夹，**不要覆盖**，换个名字或者问用户。

## 2. 复制模板

把本 Skill 的 `templates/` 里的所有内容（包括 `.gitignore`）复制到资料库文件夹。

## 3. 资料库的结构

骨架用 **PARA**（按“做的事”分，不按身份分，身份怎么叠加、怎么变都装得下），再加上**四层成长**：

```
AGENTS.md       给所有 AI 的规则（属于 Skill，升级时更新）
CLAUDE.md       让 Claude Code 也去读 AGENTS.md
设置.md         电脑名、AI 工具、报告方式、复盘时间
使用说明.md     给用户自己看的一页说明

我是谁/         基本信息、记录范围、做事风格、原则、方法论、价值观、候选洞察、关系网/
每日/           每天的事件记录和成长报告（核心，最原始的记录）

项目/           P：有目标、会结束的事
领域/           A：长期负责、不会结束的事
资源/           R：提示词、模板、资料
归档/           A：做完的项目、不再负责的领域

成长/           踩坑避坑库、周报/、月报/、结构变化记录
能力/           能力地图：SOP、检查清单、判断框架、模板、配方
产出/           一键生成的周报、述职、简历、个人画像
目标与复盘/     年度目标
收件箱/         随手丢的，复盘时归档

系统/           模块库、定时任务、接入说明、常见问题（属于 Skill，升级时更新）
```

四层成长：每日（原始记录）→ 成长（经验）→ 我是谁（认知）→ 能力（AI 拿到就能照着做）。

**升级规则**：`AGENTS.md`、`CLAUDE.md`、`系统/` 属于 Skill，以后 Skill 升级只更新这几个。其他都是用户自己的数据，升级时**永远不动**。所以个性化的内容不要写进 `AGENTS.md`，要写在 `我是谁/` 和 `设置.md` 里。

## 4. 按回答填个性化的部分

| 文件 | 填什么 |
|---|---|
| `我是谁/基本信息.md` | 第 1、3 轮的回答 |
| `我是谁/记录范围.md` | 按身份和第 6 题写出**他的**记录范围（例：上班的产品经理是“需求和项目、跨部门沟通、汇报、个人成长”；同时做副业的加上副业）；第 17 题写进“不记清单” |
| `设置.md` | 第 5 轮的回答 |
| `项目/` | 第 4 题的每个项目建一个文件，用 `项目/_模板.md` |
| `领域/` | 第 5 题的每个领域、第 11 题选了的生活模块，各建一个文件，用 `领域/_模板.md` |
| `能力/README.md` | 在能力地图里按他的工作分出领域；第 7 题的 3 件事和扫描发现的固定做法标 💡 或 📝 |
| `目标与复盘/年度目标.md` | 第 8 题 |
| 模块 | 按 `系统/模块库.md`，只建他的身份和选择需要的模块 |

## 5. 不要做的

- 不要建用户用不到的模块和空文件夹
- 不要预先写通用的岗位 SOP。能力只从他自己做过的事里长出来
- 不要把用户没确认的推断写进 `我是谁/` 的原则、方法论、价值观、做事风格。推断只能写进 `候选洞察.md`

## 6. 生成后

用一个简单的树状图给用户看建了哪些东西，每个文件夹一句话说明用途。
